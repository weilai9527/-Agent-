# 面试回答评分的离线双人盲评

用两套评分器对**同一批回答**的结果，与两位专业面试官独立给出的标签比较。只需 Python 3 标准库。工具不会访问数据库、调用模型或生成人工标签。

1. 从经授权使用的历史导出整理 CSV，每行一条回答，列为 `sample_id,candidate_id,interview_id,question,answer,rubric,old_score,new_score`。使用匿名且稳定的 ID；文本去除个人身份及历史分数。题目有追问时，`question` 包含评分所需的前文，`rubric` 写双方共用的题型评分锚点。选取样本时保留短答、错答、转写和服务失败样本。使用连续入组样本估计运行指标；刻意挑选的挑战题单独出报告。
2. 在看模型输出前冻结量表、分界和样本划分。用下列命令生成两份顺序不同的标注表，仅分发各自的一份。按候选人 ID 稳定哈希，默认约 25% 的候选人是留出组；开发时用 `--split dev`。没有候选人 ID 时可用 `--group-by interview_id`，但同一候选人的不同场次可能跨组。两个命令应使用相同的分组、比例、种子与子集。留出集不用于调权或改提示词。

   ```sh
   python3 scripts/score_blind_eval.py prepare samples.csv --out blind
   ```

3. 两位面试官独立填 `band`（必填）和 `reason`（建议引用回答证据）。两位面试官用同一套预先约定的五档行为锚点，标签 0 至 4 从低到高。题型量表要说明“基本可行”“解释清楚”“验证并指出边界”各需哪些回答证据，也要说明短而正确的回答能达到哪一档。第一次比较会列出所有分歧样本；由第三位专家在不看模型分数的情况下复核，在 `adjudication.csv` 用两列 `sample_id,band` 填写全部分歧的最终档位。两人完全一致可省去 `--adjudication`。
4. 在原样本表的 `old_score,new_score` 填写两版对同一回答实际显示的百分制分数。真实显示过的降级分也应记录，暂缓评分或无分留空（数值 0 是有效分数）。数据导出时先按来源核对旧数据里用于占位的 0。评分版本、题型量表版本和数据快照由操作者随实验保留。默认按各自分档解释分数，旧版分界上限为 30/50/70/90，新版为 20/40/60/80。如已有其他冻结分界，可分别用 `--old-cutoffs A B C D` 和 `--new-cutoffs E F G H` 覆盖。此模式考察每版按其原量尺划档后与共同人工锚点的一致性。若关心产品沿用同一套百分制决策阈值时的效果，改用 `--cutoffs 30 50 70 90` 对两版均施加同一分界。两种实验回答不同问题，均须预先锁定，不能根据留出集表现挑选。输出的 `cutoff_mode` 和 `band_cutoffs` 记录模式与两组实际分界。

   ```sh
   python3 scripts/score_blind_eval.py compare samples.csv blind/reviewer_a.csv blind/reviewer_b.csv --adjudication adjudication.csv > metrics.json
   ```

`human_agreement_before_adjudication` 给出人工仲裁前的逐题一致率和线性加权 Cohen κ。`all_samples` 同时报告出分覆盖率、低质量回答覆盖率、已出分且人工评为低档（0–1）时模型却评为高档（3–4）的比例，以及模型与最终人工标签的一致性。`both_scored` 只在两套系统都有分数的同一组回答上比较，可与全样本指标对照。所有比例同时给出分子分母，分母为零或 κ 不可识别时输出 null。低误高评率须连同覆盖率阅读；单个候选人的多条回答并非独立样本。该工具报告单题观察值，不能替代整场报告、维度分、重复评分稳定性或分岗位的单独验收，也不证明岗位表现预测效度。
