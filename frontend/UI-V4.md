默认难度的显式选择优先于档案中的历史面试偏好：简单、中等和困难会保持各自完整预设，只读取档案中的目标岗位与简历；自主配置仍可沿用历史经验、面试类型、强度和面试官风格。配置合并逻辑位于 `src/setupDefaults.js`。

简历、能力画像和个人资料已采用 V4 页面标题、色彩与卡片外观；内部表单与图表继续使用原 React 组件和真实数据。真实登录、创建面试、语音通话和报告生成需要在已配置的本地服务与测试账号下做端到端验收。

结束面试接口会先保存一条 `queued` 报告并安排后台生成。报告详情页轮询结果，完成后显示真实报告；失败时可手动重试。首页、历史和能力画像会区分生成中的报告，避免把待生成的零分当作正式评分。

能力画像分别展示已完成面试数和有效能力报告数。长期均分、趋势和维度只纳入生成成功或本地降级完成、包含候选人回答且具有数值总分的报告；排队中、失败和证据不足的报告不会参与统计。页面使用「样本积累情况」描述当前数据量，不再根据场数直接宣称画像可信度高低，并保留真实 0 分与缺失分数的区别。

开发服务默认使用 5173 端口；`frontend/vite.config.js` 将 `/api` 和 `/ws` 代理至业务后端，默认目标为 `http://127.0.0.1:3001`。运行 `npm run dev:frontend` 启动候选人端，运行 `npm run build` 构建。

## RTC 开场和面试官切换时的角色约束

- 语音轮次切换原来只调用 NotifyAgent 朗读下一题，没有替换云端模型的角色和上下文。现在先确认旧会话停止，保存下一位面试官及首问，再创建新的 RTC 会话和智能体任务。
- 切换中禁用语音开始按钮；停止失败不会启动新智能体。用户离开页面会取消自动重连，旧会话迟到的问题不会写入新轮次。切换会有一次重新连接的等待。
- 开场字幕不作为新的追问入库。提示词明确 Greeting 已负责开场，模型应等待当前问题的新回答；限定技术、架构和 HR 各轮职责，不替候选人作答，听不清时澄清。
- 回归测试覆盖停止、准备新角色、启动的顺序与失败/取消分支，并验证三轮任务的角色、题目及任务 ID。真实语音表现仍需人工实测；提示词不能保证模型永不跑偏。

## RTC 浏览器入会网络失败处理

- 最新两次失败日志显示已取得 Token，但停在 RTC `connecting`，未进入 AI 面试官启动阶段。
- 加入频道失败也执行 SDK 退出清理；仅入会网络错误（SDK 40001 / Network error）使用新客户端自动重试一次。鉴权、麦克风、发布失败不自动重试，取消后停止重试。
- 启动日志记录入会、字幕、麦克风、发布、智能体启动阶段，以及耗时和错误码；不记录 Token 或原始 SDK 响应。
- 页面改为中文网络提示，保留切换文字面试入口。此处理不能替代对持续 DNS、代理或网络阻断的排查，真实语音连接仍需浏览器实测。

## RTC 首次启动等待修复

- 语音启动只读取与当前档案匹配的已保存分析；不存在或已过期时使用本场 `resume_context`，不在开始通话时同步重新分析简历。
- 后台核对在连接与读取超时窗口之后进行，避免启动请求尚未返回就将任务判定为不存在；已返回的网络异常按 UTC 重试时间核对。明确的 4xx 拒绝（408 除外）立即结束等待。
- 后续任务查询失败保留原始启动异常。前端将任务不存在和超时转换成可操作的重连提示。
- 回归使用隔离数据库与模拟云端，覆盖缓存、过期分析、慢启动、拒绝、超时核对和失联进程恢复。实际首次语音接通仍需用户通过麦克风复测。
