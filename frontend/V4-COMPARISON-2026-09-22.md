# V4 原版与当前 React 版对照检查

日期：2026-09-22。参考：桌面 `v4` 文件夹和 5500 演示站；当前：5173 React 站。
本轮进行页面查看与代码检查，没有修改产品实现、创建面试或重新测试语音通话。简历、报告的桌面和手机显示沿用本会话刚完成的实测结果。

## 优先修复的功能问题

### 1. 简单难度被历史设置覆盖（已修复并验收）

- 原因是 `SetupPage/loadSetupDefaults` 无条件用 profile 的历史偏好覆盖当前预设，导致标题与实际提交配置不一致。
- 已调整为：默认难度只从档案读取目标岗位和简历；自主配置才沿用历史经验、面试类型、强度和面试官风格。
- 浏览器实测「简单」保持「应届 / 技术一面 / 校招 HR 面 / 八股基础 / 轻松 / 友好引导」，摘要与表单一致；没有创建测试面试。
- `src/setupDefaults.test.js` 覆盖默认预设、自主配置和接口延迟时保留用户已编辑简历三种情况。

### 2. 能力画像的样本与可信度定义不可靠（已修复并验收）

- 后端和前端已统一口径：只有生成成功或本地降级完成、包含候选人回答且有数值总分的报告才进入长期均分、趋势和能力维度；排队中、失败和证据不足的报告不再参与统计。
- 页面分别显示「已完成面试」和「有效能力报告」，并补充能力覆盖与面试类型数量。实际账号验收显示 38 场已完成、20 份有效报告、2 类面试。
- 原「画像可信度：高/中等」已改为描述性的「样本积累情况」，并明确样本进度不代表统计置信度。
- 最近报告、分差和单题依据均保留真实 0 分；只有缺失分数才显示未评分。
- 自动测试覆盖成功、降级、排队、失败、无回答和真实 0 分，完整后端测试与前端构建均通过。

### 3. 专项训练入口没有传递专项参数（点击与代码确认）

- 「开始专项训练」只进入通用电话面试方式页；`onStartTraining` 没有传入薄弱维度或任务。
- 页面显示「提升建议 3 项」，代码计算了 trainingTasks，但没有渲染任务列表。V4 原版的能力画像有「本周提升计划」。
- 建议：恢复三条真实练习任务并把选中维度带入配置；接好前可改为「开始新练习」。

### 4. 岗位、题目与评语需要统一（已观察到，生成原因待联调）

- 当前目标是「幼儿园行政助理」，20:05 报告却考查 Docker/YOLOv8/OpenCV。配置仍沿用技术面场景。
- 同一条「你好」回答在摘要中被认定未回应问题，在单题亮点中却称「回答与问题相关」。
- 训练建议还出现「评估其」「警惕简历夸大风险」等招聘方视角，候选人难以据此练习。
- 建议：题目同时约束岗位与简历；没有实质回答时明确不足；改进建议面向候选人的下一次作答。不能只通过换颜色解决。

### 5. 页面路由与返回层级（代码确认）

- V4 按 #home/#custom/#resume/#portrait/#report 区分页面。当前视图只在 React state 中，URL 一直为 #homen。
- 刷新无法恢复当前简历/报告页面，浏览器返回键无法逐页返回；有进行中面试时初始化会恢复面试页，不能笼统称所有刷新都回首页。
- 报告详情同时有「返回我的」「返回历史记录」，全局面包屑未区分历史列表与单份报告。
- 建议：统一路由和逻辑父级，保留一个明确的页面返回入口。

## 已确认的差异与保留项

- V4 有日夜主题，当前没有。属于尚未迁入的功能，暂不必优先补齐。
- 阿里云 RTC 默认且仅显示此通道、隐藏重放、合并开始/结束，是用户已确认的设计，不视为缺失。
- 文字和语音共享真实面试进度是当前业务设计。页面「独立语音面试」与「共享本场进度」措辞冲突，应改为「实时语音面试」。本轮不重新发起通话。
- 真实登录、岗位确认、候选人问答、异步报告、上传分析均应保留；V4 的演示登录、固定问题、示例分数不应迁入生产流程。
