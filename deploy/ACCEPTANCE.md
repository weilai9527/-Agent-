# 原生主路径与只读应急验收

2026-11-04 在本地工作区使用合成学校、临时数据库、回环 HTTPS 模型和一次性密钥验证。日常部署按原生运行边界验收，冻结的历史学校数据另外验证迁入和只读救援。

| 验收项 | 本轮证据 |
| --- | --- |
| 无旧后端的完整教学流程 | `python scripts/smoke_microservices.py --crash-issuance --restore-drill` 只向部署目录复制 services 和 shared，不提供 backend 与 admin_backend。两个模式变量留空；16 个 HTTP 服务均可启动。初始校管在空身份库创建，经管理网关分配教师与班级，学生作答后得到独立评估库的报告。 |
| 角色和数据归属 | 同班非负责教师可以在其权限范围只读查看记录，改分和证书审核需要负责关系和独立动作。更新后保留原版本。模型选择由评估 Worker 通过签名 HTTP 获得，控制库 SQL 和学校签发私钥按进程隔离。 |
| 任务重试、发证与撤销 | 重放相同作答不会生成第二份答案。取得签发许可后终止签发进程，再改分和重启，重试恢复原许可、原序号。存证服务离线时仍可撤销；验真不可用时文件校验返回状态未知。在新目录恢复七个教学相关库后，原签名与撤销状态一致。 |
| 学校日常事务 | 原生页面支持登记、Excel/CSV 组织和名册、一次性密码发放、职员改名和强制改密、权限申请/审批、教学大屏、学生档案、专业岗位关联、面试官模板、RTC 与安全审计。审核旧管理 82 条 HTTP 方法的具体接管路径见[归属清单](NATIVE-COVERAGE.md)。 |
| 真实浏览器与构建 | 学生端、正式管理端的 Vite 生产构建通过。管理端 Chrome 使用真实原生网关办理学校开户/归班/密码轮换，以及岗位和职业目录的导入与授权操作。前端、管理端及原型的 JS/DOM 合并回归 126 项通过。 |
| 额度和故障 | `python -m services.usage.smoke_worker_usage` 使用真实网关、独立评估 Worker 与合成模型。零预算保留作答，外部派发为零；额度恢复后评分、报告各消耗一次。强制重评等待期间保留原分。 |
| MySQL 权限与兼容 | 一次性 MySQL 8.0.36 以 13 个服务专用账户初始化及重启，复验近似学校名/账号隔离、跨库拒绝、并发开户/审批、任务投递、签发许可与改分顺序。只读验真账号可查而写入被拒；历史夹具在独立验证库重放。MySQL 生成的状态快照也核验学校归属。 |
| 只读应急 | 有效期上限一小时，工单签名绑定冻结文件摘要、学校、操作者与口令。真实工单制备、过期/撤销、跨校源、文件替换、未知状态或视图替代表、旧 Cookie、写请求和 WS 拒绝均有专项。[应急操作](EMERGENCY.md)；[恢复演练](RESTORE-DRILL.md)。 |
| 旧工具与初始部署 | 本地启动器从空目录生成各进程的独立凭据并运行原生服务。旧演示种子不再写工作区业务库，旧 E2E 入口指向隔离测试；MySQL 初始化命令输出供 DBA 审核的分域 DDL。旧 IBD 转换只向新的暂存目标原子发布。[本地启动](NATIVE-LOCAL.md)；[MySQL 部署](NATIVE-MYSQL.md)。 |
| 全量回归 | 同一临时源码快照中，服务、集成与安全套件 601 项通过，另有 21 个子用例；学生端历史回归 117 项通过，另有 4 个子用例；旧管理端按文件隔离执行 44 项通过。SQLite 跳过的两项 MySQL 专项另在真实临时 MySQL 8.0.36 中通过。未以关闭测试或恢复旧模式通过验收。 |
| 人工审核 | 已用 `python scripts/check_chinese_comments.py` 逐文件核对自有源码的注释和文档字符串，说明性英文待复核为零。权限、服务故障和数据写入点见[人工核对索引](REVIEW.md)。 |

## 学校上线前

使用学校自己的脱敏副本核对学号、任课关系、作答、报告历史、证书和撤销水位，完成备份及恢复验证。生产环境应分别配置 TLS、服务账户、可信公钥与密钥托管、持久审计卷和备份保留策略。应急工单审批机和校方签发密钥应分开管理。

已有的学校长期保存意向、正式证明的效力、视频录制期限和谁能回放，仍按校方确认执行。真实 RTC/录像、数字人、托管链、供应商账单、生产容量和生产灾备时限需在部署环境联测，本轮没有学校峰值压测。IBD 导入以合成提取数据验证，Windows PowerShell 兼容入口未在 Windows 实机执行。
