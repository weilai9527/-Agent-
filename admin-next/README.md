# 乐业通 / 星河面试 · 高校面试训练管理原型

本项目仅使用 React、React DOM、lucide-react 与 Vite，所有学生、面试报告、计划和就业状态均为演示数据，不连接后端。不修改同级旧管理端或后端项目。

## 运行与检查

使用已有依赖，无需新增依赖：

- `npm run dev`：开发服务器，地址为 http://127.0.0.1:5186
- `npm run build`：生成静态构建
- `npm run preview`：预览构建
- `npm test` 或 `node --test src`：纯函数单元测试

## 品牌、角色与路由

`src/brand.js` 根据地址路径切换品牌：默认“乐业通”，路径包含 `/xinghe/` 时为“星河面试”。侧栏、页脚、帮助和页面标题共用品牌配置。

右上角可切换校级管理员（全校）、学院管理员（计算机学院）、辅导员（林老师，软件工程 2301 班与计算机科学 2302 班）。菜单、筛选选项、列表、详情、导出、计划范围及全局搜索均遵循该角色范围。系统功能仅校级可见。范围控制仅用于前端演示，正式版必须由服务端授权。

使用轻量 hash 路由，例如 `#/overview`、`#/students?class=software2301&q=陈`、`#/students/2023010101`、`#/interviews/interview-001`、`#/plans/demo-tech`。刷新保留页面和筛选，支持浏览器前进后退；可与 `/xinghe/` 前缀和静态部署配合使用。

## 页面与交互

- 工作台：范围内学生数、本周完成面试、平均分、待辅导人数；待辅导队列、进行中计划与最近五场面试。
- 学生与班级：训练统计、独立学生档案、面试历史；辅导状态与备注可保存到本机。
- 面试记录：按每场面试展示，支持学院、班级、计划、状态及日期筛选；独立报告页展示得分、等级、能力维度和面试官反馈。
- 训练计划：目标范围多选、岗位、类型、难度、风格、日期、说明；支持草稿、编辑、发布及按日期派生的状态。
- 就业统计：醒目标注示意，汇总由当前名单计算，等待对接学校就业系统。
- 学生账号、组织架构、报告质检、职业目录、招聘岗位、岗位描述审核、模型配置、管理员与权限、安全与日志：统一功能占位，不编造业务数据。
- 个人设置：紧凑表格、只读机构名称。
- 全局搜索支持 Ctrl/Cmd + K，结果可直达学生、班级筛选、计划、报告及功能。弹窗与移动端抽屉保留焦点陷阱、退出键关闭及焦点恢复。
- 导出当前筛选结果的全部记录，字段与对应列表一致（操作列除外），确认后生成带日期的中文文件名，并提示正式版服务端导出与审计要求。

## 数据与计算口径

学生不保存面试分数或面试状态。示例含 10 位学生、20 场面试，每人 0–4 场，覆盖零分、无训练和进行中状态。演示日期相对加载日生成，便于持续演示。

“最近得分”取最近一次已完成面试；平均分取已完成且有有效分数的面试，零分计入，空样本显示“暂无”。“本周”按本地时间周一至周日，依据面试开始时间统计已完成面试（正式系统如需按完成时间统计，应补充完成时间字段）。

“需要辅导”定义为最近已完成面试分数低于 70 且没有已完成跟进记录；70 分不计入，零分计入。已安排仍留在队列。计划进度仅统计目标范围内关联本计划的已完成面试，按学生去重。草稿优先，其余状态按开始/截止日期派生，截止当天仍有效。

浏览器存储键均独立定义在 `constants.js`。用户计划（以及演示草稿的本机编辑副本）、追加的辅导记录、显示偏好与当前演示角色分别存储；不按编号判断用户计划。清除本地存储可重置原型，旧版存储键不再读取。角色间可看到权限范围内同一份本机数据。

## 目录

- `main.jsx`：仅挂载应用
- `App.jsx`、`context.jsx`：页面装配与共享状态
- `brand.js`、`router.js`、`navigation.js`：品牌、路由、导航
- `data.js`、`constants.js`、`roles.js`、`selectors.js`：实体、枚举、范围与纯函数统计
- `components/`：徽标、头像、弹窗、表格、分页、筛选、导出、搜索等公共组件
- `layout/`：侧栏和顶栏
- `pages/`：各列表、详情、报告、计划表单与设置页面
- `*.test.js`：无需浏览器运行的单元测试；`src/index.js` 为 `node --test src` 提供目录入口
- `styles.css`、`workspace.css`、`refinements.css`：原视觉样式与本次补充

## 后续对接

需要后端提供真实角色授权、报告与质检接口、服务端导出审计和就业去向数据。当前发布计划不下发真实任务；辅导状态与计划仅保存于本机。待产品确认同一学生在完成辅导后再次取得低分时，是否应按新面试重新进入队列（本原型按“存在已完成跟进则排除”的任务规则实现）。
