# 合成学校档案恢复演练

在仓库根目录执行以下命令。演练需要 macOS 或 Linux 本机的回环端口，以及现有烟测的 Python 依赖。它创建一次性的学校、师生、数据库和签名密钥，无需提供实际学校数据路径。

```sh
python scripts/smoke_microservices.py --assessment-mode isolated --crash-issuance --restore-drill
python -m pytest -q tests/integration/test_archive_drill.py
```

第一条命令从学生提交答案开始，经过评分、教师改分、发证审核和撤销。签发进程在评估许可提交后被终止，教师改分后由原许可恢复发证。溯源服务在撤销前离线，因此归档中应保留尚待投递的撤销事件。所有业务 API 与后台 Worker 停止后，测试记录源事件序号、评估收件回执、任务状态、评分版本、发证 outbox 等水位，再分别通过 SQLite backup API 备份身份、教学、面试、评估、分析、证书和存证这七个合成业务库。

恢复要求完整文件集合、由调用方独立留存的 manifest 摘要、逐文件 SHA-256、SQLite 完整性与外键检查以及一致的事件水位。所有检查先在空的临时目录执行，通过后才发布新的恢复目录。同一演练主动提供缺失和篡改文件，验证不能发布不完整的恢复目录。测试最后核对训练尝试、回答、改分原因、审核意见、签发许可、原序号、原签名和已撤销状态，并在独立进程中用原学校公钥通过公开验真 ASGI 入口重新验签。第二条命令另外构造仅位于 WAL 的已提交撤销，验证备份不依赖主文件已经 checkpoint。

本演练覆盖指定合成场景的停写恢复。实际学校还需分别制定备份访问授权、加密、离线防删副本、密钥灾备、保留与删除规则，并在自身的数据库和存储中验证恢复目标。此次结果不覆盖 MySQL 日志恢复、其他业务域、真实模型或链供应商、音视频对象、KMS 私钥恢复、在线跨库快照，也不提供生产 RPO/RTO 或容量结论。合成备份和恢复文件在演练结束时自动清理。
